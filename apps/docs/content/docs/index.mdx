## How the pieces fit

1. **Your application publishes an event** using a project API key.
2. **Cascadehook creates deliveries** for enabled, subscribed endpoints.
3. **Your receiver verifies the signature** and durably accepts the event.
4. **You inspect the result** in the dashboard or through the API.

An event being accepted and a webhook being delivered are separate outcomes.
An HTTP `202` confirms publication. A delivery marked `succeeded` confirms that
the receiver acknowledged it.
